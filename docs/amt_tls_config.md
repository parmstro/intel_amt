# amt_tls_config - Configure TLS/HTTPS and Certificates for Intel AMT

## Synopsis

- Enable or disable HTTPS on Intel AMT management interface
- Upload TLS certificates to AMT for secure connections
- Integrates with Red Hat Identity Management (IDM/IPA) via certmonger
- Supports manual certificate upload from PEM files
- Configures TLS port settings (HTTP: 16992, HTTPS: 16993)
- Essential for securing AMT management traffic

## ⚠️ Compatibility Requirements

**This module requires Intel AMT in Enterprise Mode with TLS support.**

### Supported Configurations:
- ✅ Intel AMT 11.x or newer (any mode)
- ✅ Intel AMT 8.x-10.x in **Enterprise Mode** with vPro
- ✅ Systems with TLS PKI menu available in MEBx

### NOT Supported:
- ❌ Intel AMT in **Small Business Mode** (TLS not available)
- ❌ Intel AMT 10.0.56 on Intel NUC5i5MYBE (Small Business Mode)
- ❌ Systems without TLS PKI configuration in MEBx
- ❌ Standard Manageability (non-vPro) SKUs

**Check Your AMT Mode:**
1. Boot system and press Ctrl+P to enter Intel MEBx
2. Look for "TLS PKI" menu under AMT Configuration
3. If TLS PKI menu is present: Enterprise Mode ✅
4. If no TLS PKI menu: Small Business Mode ❌ (HTTPS not available)

See [AMT_10_TLS_LIMITATION.md](../AMT_10_TLS_LIMITATION.md) for detailed compatibility information.

## Parameters

| Parameter | Choices/Defaults | Comments |
|-----------|------------------|----------|
| **host**<br/>string / required | | Hostname or IP address of the AMT management interface |
| **username**<br/>string / required | | AMT admin username |
| **password**<br/>string / required | | AMT admin password<br/>(no_log: true) |
| **port**<br/>integer | Default: 16992 | AMT management port for this configuration operation<br/>Use 16992 for HTTP, 16993 for HTTPS |
| **use_tls**<br/>boolean | Default: false | Whether to use TLS for THIS configuration connection<br/>Set to false when connecting via HTTP to enable HTTPS |
| **verify_ssl**<br/>boolean | Default: false | Whether to verify SSL certificates for this connection |
| **tls_enabled**<br/>boolean | | Enable or disable HTTPS on AMT<br/>When true, AMT accepts connections on port 16993<br/>When false, only HTTP on port 16992 is available |
| **certificate_path**<br/>path | | Path to PEM-encoded certificate file<br/>Can be certificate generated by certmonger/IPA<br/>Must contain full certificate chain if needed |
| **private_key_path**<br/>path | | Path to PEM-encoded private key file<br/>Required when certificate_path is provided<br/>(no_log: true) |
| **ca_certificate_path**<br/>path | | Path to PEM-encoded CA certificate file<br/>Establishes trust chain for AMT certificate |
| **certmonger_request**<br/>boolean | Default: false | Request new certificate via certmonger/IPA before upload |
| **certmonger_nickname**<br/>string | | Nickname for certmonger certificate request<br/>Used as identifier in certmonger tracking |
| **certmonger_subject**<br/>string | | Subject DN for certificate request<br/>Example: CN=nuc01.amt.example.com,O=Example Org |
| **certmonger_principal**<br/>string | | Kerberos principal for IPA certificate request<br/>Example: host/nuc01.amt.example.com@EXAMPLE.COM |
| **http_port**<br/>integer | Default: 16992 | HTTP port number (non-TLS)<br/>Change only for non-standard configurations |
| **https_port**<br/>integer | Default: 16993 | HTTPS port number (TLS)<br/>Change only for non-standard configurations |

## Return Values

| Key | Type | Description | Sample |
|-----|------|-------------|--------|
| **changed** | boolean | Whether configuration was changed | true |
| **tls_enabled** | boolean | Current TLS enabled status | true |
| **certificate_uploaded** | boolean | Whether a certificate was uploaded | true |
| **certmonger_request_id** | string | Certmonger request tracking ID | "20260530120000" |
| **https_port** | integer | HTTPS port number | 16993 |
| **http_port** | integer | HTTP port number | 16992 |
| **msg** | string | Human-readable operation message | "TLS enabled and certificate uploaded successfully" |
| **warnings** | list | Warning messages about limitations | See notes |

## Examples

### Enable HTTPS with Existing Certificate

```yaml
- name: Upload certificate and enable HTTPS
  parmstro.intel_amt.amt_tls_config:
    host: nuc01.amt.example.com
    username: admin
    password: "{{ amt_password }}"
    port: 16992
    use_tls: false
    tls_enabled: true
    certificate_path: /etc/pki/amt/nuc01.crt
    private_key_path: /etc/pki/amt/nuc01.key
    ca_certificate_path: /etc/ipa/ca.crt
```

### Request Certificate from Red Hat IPA

```yaml
- name: Request certificate from IPA via certmonger
  parmstro.intel_amt.amt_tls_config:
    host: c1s2n2.amt.parmstrong.ca
    username: admin
    password: "{{ amt_password }}"
    port: 16992
    use_tls: false
    tls_enabled: true
    certmonger_request: true
    certmonger_nickname: "amt-c1s2n2"
    certmonger_subject: "CN=c1s2n2.amt.parmstrong.ca"
    certmonger_principal: "host/c1s2n2.amt.parmstrong.ca@PARMSTRONG.CA"
    certificate_path: /var/lib/certmonger/amt/c1s2n2.crt
    private_key_path: /var/lib/certmonger/amt/c1s2n2.key
```

### Disable HTTPS (Revert to HTTP)

```yaml
- name: Disable HTTPS on AMT
  parmstro.intel_amt.amt_tls_config:
    host: nuc01.amt.example.com
    username: admin
    password: "{{ amt_password }}"
    port: 16993
    use_tls: true
    tls_enabled: false
```

### Renew Certificate

```yaml
- name: Upload renewed certificate
  parmstro.intel_amt.amt_tls_config:
    host: nuc01.amt.example.com
    username: admin
    password: "{{ amt_password }}"
    port: 16993
    use_tls: true
    certificate_path: /etc/pki/amt/nuc01-renewed.crt
    private_key_path: /etc/pki/amt/nuc01-renewed.key
```

## Use Cases

### Secure AMT Fleet with Red Hat IPA

```yaml
- name: Configure HTTPS on all NUC systems with IPA certificates
  hosts: localhost
  gather_facts: false
  vars:
    amt_domain: amt.parmstrong.ca
    realm: PARMSTRONG.CA
    nuc_hosts:
      - c1s1n1
      - c1s1n2
      - c1s2n1
      - c1s2n2

  tasks:
    - name: Request and configure HTTPS for each NUC
      parmstro.intel_amt.amt_tls_config:
        host: "{{ item }}.{{ amt_domain }}"
        username: admin
        password: "{{ amt_password }}"
        port: 16992
        use_tls: false
        tls_enabled: true
        certmonger_request: true
        certmonger_nickname: "amt-{{ item }}"
        certmonger_subject: "CN={{ item }}.{{ amt_domain }}"
        certmonger_principal: "host/{{ item }}.{{ amt_domain }}@{{ realm }}"
        certificate_path: "/var/lib/certmonger/amt/{{ item }}.crt"
        private_key_path: "/var/lib/certmonger/amt/{{ item }}.key"
      loop: "{{ nuc_hosts }}"
      async: 300
      poll: 0
      register: tls_jobs

    - name: Wait for TLS configuration
      ansible.builtin.async_status:
        jid: "{{ item.ansible_job_id }}"
      loop: "{{ tls_jobs.results }}"
      register: job_result
      until: job_result.finished
      retries: 30
      delay: 10
```

### Manual Certificate Workflow

```yaml
- name: Generate certificates manually and upload
  hosts: localhost
  gather_facts: false

  tasks:
    - name: Create certificate directory
      ansible.builtin.file:
        path: /etc/pki/amt
        state: directory
        mode: '0755'

    - name: Generate private key
      community.crypto.openssl_privatekey:
        path: /etc/pki/amt/nuc01.key
        size: 2048

    - name: Generate CSR
      community.crypto.openssl_csr:
        path: /etc/pki/amt/nuc01.csr
        privatekey_path: /etc/pki/amt/nuc01.key
        common_name: nuc01.amt.example.com
        organization_name: Example Org

    - name: Generate self-signed certificate (for testing)
      community.crypto.x509_certificate:
        path: /etc/pki/amt/nuc01.crt
        privatekey_path: /etc/pki/amt/nuc01.key
        csr_path: /etc/pki/amt/nuc01.csr
        provider: selfsigned

    - name: Upload certificate to AMT
      parmstro.intel_amt.amt_tls_config:
        host: nuc01.amt.example.com
        username: admin
        password: "{{ amt_password }}"
        port: 16992
        use_tls: false
        tls_enabled: true
        certificate_path: /etc/pki/amt/nuc01.crt
        private_key_path: /etc/pki/amt/nuc01.key
```

### Transition HTTP to HTTPS Fleet

```yaml
- name: Secure existing HTTP-only AMT fleet
  hosts: localhost
  gather_facts: false

  tasks:
    - name: Check current status via HTTP
      parmstro.intel_amt.amt_host_status:
        host: "{{ item }}"
        username: admin
        password: "{{ amt_password }}"
        port: 16992
        use_tls: false
      loop: "{{ amt_hosts }}"
      register: pre_status

    - name: Enable HTTPS with certificates
      parmstro.intel_amt.amt_tls_config:
        host: "{{ item }}"
        username: admin
        password: "{{ amt_password }}"
        port: 16992
        use_tls: false
        tls_enabled: true
        certmonger_request: true
        certmonger_nickname: "amt-{{ item | regex_replace('\\..*', '') }}"
        certmonger_subject: "CN={{ item }}"
        certmonger_principal: "host/{{ item }}@{{ realm }}"
        certificate_path: "/var/lib/certmonger/amt/{{ item }}.crt"
        private_key_path: "/var/lib/certmonger/amt/{{ item }}.key"
      loop: "{{ amt_hosts }}"

    - name: Verify HTTPS connectivity
      parmstro.intel_amt.amt_host_status:
        host: "{{ item }}"
        username: admin
        password: "{{ amt_password }}"
        port: 16993
        use_tls: true
        verify_ssl: false
      loop: "{{ amt_hosts }}"
      register: post_status

    - name: Confirm all systems secured
      ansible.builtin.assert:
        that:
          - post_status.results | length == amt_hosts | length
        fail_msg: "Not all systems successfully transitioned to HTTPS"
        success_msg: "All {{ amt_hosts | length }} systems now using HTTPS"
```

### Certificate Renewal Automation

```yaml
- name: Automated certificate renewal
  hosts: localhost
  gather_facts: false

  tasks:
    - name: Check certificate expiration
      ansible.builtin.command:
        cmd: "ipa-getcert list -n amt-{{ item }}"
      loop: "{{ amt_hosts }}"
      register: cert_status
      changed_when: false

    - name: Identify certificates needing renewal
      ansible.builtin.set_fact:
        renew_hosts: "{{ cert_status.results | selectattr('stdout', 'search', 'expires:.*days') | map(attribute='item') | list }}"

    - name: Renew certificates
      ansible.builtin.command:
        cmd: "ipa-getcert resubmit -n amt-{{ item }}"
      loop: "{{ renew_hosts }}"
      when: renew_hosts | length > 0

    - name: Wait for renewal
      ansible.builtin.pause:
        seconds: 30
      when: renew_hosts | length > 0

    - name: Update AMT with renewed certificates
      parmstro.intel_amt.amt_tls_config:
        host: "{{ item }}"
        username: admin
        password: "{{ amt_password }}"
        port: 16993
        use_tls: true
        certificate_path: "/var/lib/certmonger/amt/{{ item }}.crt"
        private_key_path: "/var/lib/certmonger/amt/{{ item }}.key"
      loop: "{{ renew_hosts }}"
      when: renew_hosts | length > 0
```

## Important Notes

### AMT 10.0.56 Limitations

⚠️ **Intel AMT 10.0.56 has limited WSMAN certificate management support**

This module attempts to configure TLS via WSMAN, but AMT 10.0.56 may require **manual certificate configuration** via:

1. **Intel MEBx** (Management Engine BIOS Extension)
   - Press Ctrl+P during boot
   - Navigate to certificate configuration
   - Manually import certificate and key

2. **AMT Web Interface**
   - Access via https://hostname:16993 (if already configured)
   - Navigate to security/certificate settings

3. **Intel Manageability Commander Tool**
   - Specialized tool for AMT configuration

**What This Module Does:**
- Manages certmonger certificate requests ✅
- Prepares certificate files in correct format ✅
- Attempts WSMAN certificate upload (may not work on AMT 10.0.56) ⚠️
- Provides clear warnings and next steps ✅

### Certificate Requirements

- **Format**: PEM-encoded X.509 certificates
- **Private Key**: Must be unencrypted (no password protection)
- **Subject CN**: Should match AMT hostname for proper verification
- **Chain**: Include intermediate certificates if needed
- **Key Size**: Minimum 2048-bit RSA recommended

### Security Considerations

1. **Always enable HTTPS in production** - HTTP transmits credentials in cleartext
2. **Use trusted CA certificates** - Self-signed certificates acceptable for testing only
3. **Protect private keys** - Store with restricted permissions (0600)
4. **Regular renewal** - Implement automated certificate renewal
5. **Verify connectivity** - Test HTTPS before disabling HTTP

### Certmonger Integration

**Prerequisites:**
- Red Hat Enterprise Linux with IPA client installed
- System enrolled in IPA domain
- Sufficient privileges to request certificates
- `ipa-getcert` command available

**Benefits:**
- Automatic certificate issuance from IPA CA
- Integrated renewal tracking
- Kerberos principal binding
- Centralized certificate management

### Port Configuration

| Port | Protocol | Purpose | Default |
|------|----------|---------|---------|
| 16992 | HTTP | Non-TLS management | ✅ Enabled |
| 16993 | HTTPS | TLS-encrypted management | Disabled (enable with this module) |

### Transition Strategy

**Recommended approach:**
1. Connect via HTTP (port 16992)
2. Upload certificate
3. Enable HTTPS
4. Verify HTTPS connectivity (port 16993)
5. Consider keeping HTTP enabled for recovery
6. Document recovery procedure

**DO NOT:**
- Disable HTTP before verifying HTTPS works
- Use same port for both HTTP and HTTPS
- Forget to update firewall rules for port 16993

## Protocol Details

This module uses WS-Management (WSMAN) to configure TLS:
- CIM resource: `AMT_TLSSettingData`
- Certificate upload: `AMT_PublicKeyManagementService`
- Method: `AddCertificate`
- Authentication: HTTP Digest Authentication (initial connection may be HTTP)

**Note**: AMT 10.0.56 WSMAN limitations may require manual configuration via Intel MEBx.

## Troubleshooting

### Certificate Upload Fails

If WSMAN certificate upload fails:
```yaml
# The module will provide warnings with manual steps
# Check module output warnings for guidance
```

Manual upload via MEBx:
1. Reboot system
2. Press Ctrl+P at boot
3. Enter AMT admin password
4. Navigate to: Remote Setup and Configuration → TLS PKI
5. Import certificate and private key

### HTTPS Not Accessible After Configuration

1. Verify certificate was actually uploaded (check warnings)
2. Ensure firewall allows port 16993
3. Check AMT event logs for errors
4. Try manual MEBx configuration
5. Verify certificate matches hostname

### Certmonger Request Fails

```bash
# Check certmonger status

```
